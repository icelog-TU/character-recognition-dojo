# Firebase Account And Device Setup

This app uses one cloud-sync mode:

- Account profile mode: `accounts/{uid}/profiles/{profileId}` stores progress.
- Device records under `accounts/{uid}/devices/{deviceId}` only identify a phone/tablet and remember the active profile.

Do not manually create normal customer accounts, profiles, or devices in Firestore. The app creates them after the parent signs in.

## Console Steps

1. Open Firebase Console for `character-recognition-dojo`.
2. Go to Authentication -> Sign-in method.
3. Enable Google as the parent account sign-in provider.
4. Anonymous sign-in is not required for the app's account device sync.
5. Go to Authentication -> Settings -> Authorized domains.
6. Confirm `icelog-tu.github.io` is listed. Add it if it is missing.
7. Go to Firestore Database -> Rules.
8. Paste and publish the rule template below.

## Firestore Data Model

Production account mode:

```text
accounts/{uid}
  accountId
  email
  displayName
  plan: "family"
  maxDevices: 3
  maxProfiles: 3
  status: "active"
  updatedAt

accounts/{uid}/devices/{deviceId}
  deviceId
  label
  active: true
  activeProfileId
  ownerUid
  userAgent
  freeBrowse: true | false
  lastSeenAt
  updatedAt

accounts/{uid}/profiles/{profileId}
  profileId
  label
  active: true
  kind: "child" | "teacher" | "test"
  progress fields...
```

The `deviceId` is generated by the app and stored in browser local storage. The parent may rename the device `label`, but `deviceId` is the stable tracking identifier.

Progress belongs to profiles, not devices. One account may have up to three active learning profiles, such as `媽媽`, `哥哥`, and `妹妹`. Any phone or tablet signed in to the same account can see those profiles and switch `activeProfileId`. Two devices that use the same profile sync the same progress, while different profiles keep separate progress.

## Teacher Free Browse

Free browsing is not a user setting. To authorize a teacher/parent device:

1. Sign in on that device.
2. Open Settings and copy the system device ID.
3. In Firestore, open `accounts/{uid}/devices/{deviceId}`.
4. Set `freeBrowse` to `true`.

Only teacher-owned devices should receive `freeBrowse: true`. Normal customer devices should not.

## Device Limit

The current app checks a maximum of three active devices before registering a new device. This is enough for app testing and early family use.

For paid public release, enforce the three-device limit with a server-side Cloud Function or other trusted backend. Firestore Security Rules cannot reliably count active sibling device documents by themselves, so client-only checking is not enough for payment-grade enforcement.

## Profile Limit

The current app checks a maximum of three active learning profiles before creating a new profile. This is the customer-facing model: one family account can hold, for example, `媽媽`, `哥哥`, and `妹妹`.

For paid public release, enforce the three-profile limit with the same trusted backend used for device registration. Firestore Security Rules cannot reliably count active sibling profile documents by themselves.

## Rule Template

This rule template allows signed-in users to read/write only their own account documents.

```js
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() {
      return request.auth != null;
    }

    function ownsAccount(accountId) {
      return signedIn() && request.auth.uid == accountId;
    }

    function hasNoServerManagedFields() {
      return !request.resource.data.keys().hasAny([
        'freeBrowse',
        'role',
        'trustedFreeBrowse'
      ]);
    }

    function preservesServerManagedFields() {
      return !request.resource.data.diff(resource.data).affectedKeys().hasAny([
        'freeBrowse',
        'role',
        'trustedFreeBrowse'
      ]);
    }

    match /accounts/{accountId} {
      allow read, create, update: if ownsAccount(accountId);
      allow delete: if false;

      match /devices/{deviceId} {
        allow read: if ownsAccount(accountId);
        allow create: if ownsAccount(accountId) && hasNoServerManagedFields();
        allow update: if ownsAccount(accountId) && preservesServerManagedFields();
        allow delete: if false;
      }

      match /profiles/{profileId} {
        allow read: if ownsAccount(accountId);
        allow create: if ownsAccount(accountId) && hasNoServerManagedFields();
        allow update: if ownsAccount(accountId) && preservesServerManagedFields();
        allow delete: if false;
      }
    }

    match /audioReviews/{reviewId} {
      allow read: if true;
      allow create, update: if signedIn()
        && request.resource.data.updatedByUid == request.auth.uid
        && request.resource.data.repo == 'icelog-TU/character-recognition-dojo'
        && request.resource.data.keys().hasOnly([
          'version',
          'repo',
          'unit',
          'ref',
          'commitSha',
          'sourcePath',
          'itemCount',
          'approvedCount',
          'approvedAll',
          'pendingKeys',
          'approvalState',
          'updatedByUid',
          'updatedByEmail',
          'updatedByName',
          'updatedAt'
        ]);
      allow delete: if false;
    }

    match /assetReviews/{reviewId} {
      allow read: if true;
      allow create, update: if signedIn()
        && request.resource.data.updatedByUid == request.auth.uid
        && request.resource.data.repo == 'icelog-TU/character-recognition-dojo'
        && request.resource.data.keys().hasOnly([
          'version',
          'repo',
          'unit',
          'ref',
          'commitSha',
          'sourcePath',
          'sentenceCount',
          'extraAudioCount',
          'repairCount',
          'reviewComplete',
          'repairItems',
          'updatedByUid',
          'updatedByEmail',
          'updatedByName',
          'updatedAt'
        ]);
      allow delete: if false;
    }
  }
}
```

Do not add a user-facing legacy device-code field or editable device-name field back to Settings. Normal users should see account sign-in, the three learning profiles under that account, editable learning-profile names, and the system-generated device ID only as support/admin diagnostic information.

`audioReviews` is for teacher QA of production audio. `assetReviews` is for post-merge teacher repair queues for images and audio. Both are intentionally separate from child progress and can be public-read because they contain only lesson id, commit SHA, public asset paths, and teacher approval/repair status for already-public assets. Review pages must read these documents even before sign-in so the teacher can see the same current review state on phone and tablet. Writes still require Google sign-in so random visitors cannot approve, clear, or mark repair work. If a teacher changes checkboxes or notes while not signed in, that change is browser-local and must not be considered cross-device synced.

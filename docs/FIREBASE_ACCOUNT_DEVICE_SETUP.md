# Firebase Account And Device Setup

This app uses two cloud-sync modes during the transition period:

- Production account mode: `accounts/{uid}/devices/{deviceId}`.
- Legacy teacher/test mode: `devices/{deviceCode}`.

Do not manually create normal customer accounts or devices in Firestore. The app creates account/device records after the parent signs in.

## Console Steps

1. Open Firebase Console for `character-recognition-dojo`.
2. Go to Authentication -> Sign-in method.
3. Keep Anonymous enabled for the current legacy teacher/test device-code flow.
4. Enable Google as the parent account sign-in provider.
5. Go to Authentication -> Settings -> Authorized domains.
6. Confirm `icelog-tu.github.io` is listed. Add it if it is missing.
7. Go to Firestore Database -> Rules.
8. Paste and publish the rule template below.

## Firestore Data Model

Production account mode:

```text
accounts/{uid}
  accountId
  email
  displayName
  plan: "family"
  maxDevices: 3
  status: "active"
  updatedAt

accounts/{uid}/devices/{deviceId}
  deviceId
  label
  active: true
  ownerUid
  userAgent
  freeBrowse: true | false
  lastSeenAt
  updatedAt
  progress fields...
```

The `deviceId` is generated by the app and stored in browser local storage. The parent may rename `label`, but `deviceId` is the stable tracking identifier.

Legacy teacher/test mode:

```text
devices/{deviceCode}
  deviceCode
  label
  freeBrowse: true | false
  progress fields...
```

## Teacher Free Browse

Free browsing is not a user setting. To authorize a teacher/parent device:

1. Sign in on that device.
2. Open Settings and copy the system device ID.
3. In Firestore, open `accounts/{uid}/devices/{deviceId}`.
4. Set `freeBrowse` to `true`.

Only teacher-owned devices should receive `freeBrowse: true`. Normal customer devices should not.

## Device Limit

The current app checks a maximum of three active devices before registering a new device. This is enough for app testing and early family use.

For paid public release, enforce the three-device limit with a server-side Cloud Function or other trusted backend. Firestore Security Rules cannot reliably count active sibling device documents by themselves, so client-only checking is not enough for payment-grade enforcement.

## Rule Template

This rule template allows signed-in users to read/write only their own account documents and keeps legacy anonymous device-code sync working during the transition.

```js
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() {
      return request.auth != null;
    }

    function ownsAccount(accountId) {
      return signedIn() && request.auth.uid == accountId;
    }

    function hasNoServerManagedFields() {
      return !request.resource.data.keys().hasAny([
        'freeBrowse',
        'role',
        'trustedFreeBrowse'
      ]);
    }

    function preservesServerManagedFields() {
      return !request.resource.data.diff(resource.data).affectedKeys().hasAny([
        'freeBrowse',
        'role',
        'trustedFreeBrowse'
      ]);
    }

    match /accounts/{accountId} {
      allow read, create, update: if ownsAccount(accountId);
      allow delete: if false;

      match /devices/{deviceId} {
        allow read: if ownsAccount(accountId);
        allow create: if ownsAccount(accountId) && hasNoServerManagedFields();
        allow update: if ownsAccount(accountId) && preservesServerManagedFields();
        allow delete: if false;
      }
    }

    // Temporary legacy path for teacher/test device-code sync.
    // Remove this path before a payment-grade public release.
    match /devices/{deviceCode} {
      allow read: if signedIn();
      allow create: if signedIn() && hasNoServerManagedFields();
      allow update: if signedIn() && preservesServerManagedFields();
      allow delete: if false;
    }
  }
}
```

Before public sales, replace the broad legacy `devices/{deviceCode}` write permission with a backend-managed flow or remove the legacy path entirely.
